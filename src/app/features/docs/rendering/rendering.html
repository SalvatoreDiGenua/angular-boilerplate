SSR + hydration

Render useful HTML first. Hydrate only what needs to wake up.

The boilerplate is designed for hybrid rendering: server output becomes the initial UI, hydration reuses it, and deferrable views can control when expensive islands are loaded and hydrated.

Incremental hydration example

A useful pattern for expensive UI.

Render the component on the server, keep its client dependencies deferred, and hydrate it when the user actually interacts with it. This is especially useful for dashboards, charts, editors and secondary widgets. 

          
@defer (on idle; hydrate on interaction) {
  <heavy-widget />
} @placeholder {
  <div class="h-64">Widget preview</div>
} @loading {
  <div>Loading widget…</div>
} @error {
  <div>Widget unavailable.</div>
}

Hybrid rendering

Choose the rendering mode per route. 

          
export const serverRoutes: ServerRoute[] = [
  { path: '',        renderMode: RenderMode.Prerender },
  { path: 'account', renderMode: RenderMode.Server },
  { path: '**',      renderMode: RenderMode.Client },
];

The right choice is driven by content: prerender public, stable pages; use SSR for request-specific HTML; keep browser-only experiences client rendered when server rendering provides little value.
